## describe

The items below the rule rank by how often a release touched a function. These first ones rank above them all, because the fix hunk itself was read and identified. `located` means the hunk is named with its evidence; `plausible` means the hunk matches the CWE and the release carries other work the diff cannot separate from it. Evidence strings are in `tools/cve_fix_verdicts.json`.

- [history CVE-2023-25516] located: CWE-190. Fix in kgmmuValidateFabricBaseAddress_GA100, knvlinkValidateFabricBaseAddress_GV100. The control method reaching the validator, subdeviceCtrlCmdGpuSetFabricAddr (0x2080016f), carries NON_PRIVILEGED in the NVOC export table, so a flag-based inventory reads it as reachable. Its handler body then calls rmclientIsCapableOrAdmin(NV_RM_CAP_EXT_FABRIC_MGMT) and returns NV_ERR_INSUFFICIENT_PERMISSIONS below that level. A compute,utility container holds no fabric-management capability, so this path is closed to the modelled attacker.
- [history CVE-2024-0090] located: CWE-787. Fix in _vidmemPmaAllocate. Reached from video memory allocation with a caller-supplied size and page size: NV_ESC_RM_ALLOC_MEMORY and the NV01_MEMORY_LOCAL_USER class allocation. Both are non-privileged.
- [history CVE-2024-53869] located: CWE-459. Fix in uvm_vm_open_semaphore_pool. UVM_ALLOC_SEMAPHORE_POOL on /dev/nvidia-uvm, then mmap of the pool range, then fork. The R550 bracket is weaker evidence: 550.142 already carries the same hunk, so the change reached that branch before the release the bulletin names.
- [history CVE-2025-23277] located: CWE-284. Fix in nv_dma_buf_map. The export side is NV_ESC_EXPORT_TO_DMABUF_FD on /dev/nvidiaN, non-privileged. The map side runs when an importer attaches to the exported dma-buf, so a reproducer needs a second device driver importing it, and that is out of reach from ioctls on the NVIDIA nodes alone.
- [history CVE-2025-23280] plausible: CWE-416. Fix in threadStateAlloc, threadStateFree, dupMemory. Same path as CVE-2025-23332: UVM_MAP_EXTERNAL_ALLOCATION reaching dupMemory.
- [history CVE-2025-23300] plausible: CWE-476. Fix in stdmemValidateParams, memdescCreate. NV_ESC_RM_ALLOC_MEMORY and the NVOS32 allocation path with size 0. Non-privileged.
- [history CVE-2025-23332] plausible: CWE-476. Fix in dupMemory. dupMemory is the UVM to RM bridge reached from UVM_MAP_EXTERNAL_ALLOCATION on /dev/nvidia-uvm, with an NV01_MEMORY_DEVICELESS handle allocated over /dev/nvidiactl first.
- [history CVE-2026-24195] plausible: CWE-20. Fix in uvm_va_range_remove_gpu_va_space, uvm_va_range_unregister_gpu. UVM_ALLOC_DEVICE_P2P creates the range. Reaching the hunk needs two registered GPUs in one VA space and an unregister of the one that does not own the range, so a single-GPU instance cannot reproduce it.
