# Mistakes

Process errors and what avoids them next time. About us, not about the driver.

Audience: the next agent running that phase. A mistake worth recording is one
that cost a round, produced a wrong number, or would repeat.

Generalise. "Marked the phase done on the subagent's assertion without reading
the smoke log" is reusable; the same sentence naming one crash is not.

PUBLIC REPO: process notes only, never findings.

Appended by `tools/knowledge_ctl.py note --kind mistake`. Do not hand-edit:
the tool timestamps and locks, and hand-edits are how the format rots.

## 2026-08-24T15:34:46+00:00 — provision
Tags: container, threat-model, scope
A container tenant's device set is decided by the code that runs when the container's mount namespace is built, and a host-side enumeration says nothing about it. A reading of libnvidia-container that stopped at the device list in src/nvc_info.c and the host mknod in src/nvc.c concluded that a node reaches a default tenant, while the mount gate at src/nvc_mount.c:786 skips that node's minor unless the OPT_DISPLAY flag is set, and src/options.h:100 leaves the display capability out of the default set. The error ran in the direction that widens scope and would have overturned a correct threat-model line. Two rules follow. Read the function that assembles the container's own device set before calling a node reachable. State the injection path alongside any such conclusion, because the CDI path and the legacy path in this stack disagree about two device families and a conclusion naming neither path states nothing.

## 2026-08-24T17:16:10+00:00 — provision
Tags: provision, toolchain, go
Go version floors do not behave the way other toolchain floors do, and assuming they do produced a wrong sentence in shipped documentation. The pinned syzkaller declares go 1.26.0 in go.mod, and the conclusion drawn was that a distribution package at 1.22 cannot build it. Go 1.21 and later read the directive and download the named toolchain on demand, because GOTOOLCHAIN defaults to auto. The evidence was already on the machine and went unread: go version reported go1.22.2 while the compile gate passed, and the module cache held golang.org/toolchain@v0.0.1-go1.26.0.linux-amd64. A local toolchain older than a declared floor is therefore not by itself a failure. The real failure conditions are a toolchain below 1.21, GOTOOLCHAIN set to local, or no route to proxy.golang.org. The rule this restates: when a tool passes on the machine while the reasoning says it should fail, the reasoning is what to check first.

## 2026-08-24T18:01:20+00:00 — eval
Tags: surface, briefs, denominator
Adding a family to the surface moved every artefact and every tool that reads them, and left the phase briefs behind. tools/surface_cov.py FAMILIES, regression_check.py TARGET_FLOOR, the EXCLUDED list and refgen.py all carried the drm family, and agents/eval.md still enumerated a denominator summing to 828 and an exclusion count of 347 against a measured 852 and 351, while agents/report.md carried the same figures into the customer-facing deliverable and named five exclusion groups where six are counted. agents/describe.md stated the compile verdict as 862 syscalls where the gate reports 957. Every check passed throughout, because regression_check.py agents reads the command lines out of a brief and checks them against the tool's argparse parser, and nothing reads the numbers in the prose. The rule: a brief is code that a model executes, and a number in it is an assertion with no test behind it. When a change moves a measured quantity, grep every brief for the old value in the same commit, and prefer a brief that names the command producing a figure over one that quotes the figure.

## 2026-08-24T19:17:03+00:00 — eval
Tags: spend, budget, ledger
A spend ledger that exists is not a ledger that received every write. campaign_ctl.bill_run catches OSError from record_run_hours, prints a warning and returns without billing, and an unattended loop reads no warnings. pipeline_ctl round-end leaves the same divergence by another route: end_round saves the round's hours and the ledger writes follow, so a write that raises there leaves the hours on record and out of the ledger. spend_for_budget read the ledger alone, so the cap saw headroom that had already been spent and the loop kept admitting campaigns. Reproduced with three bills of 1000 h lost to OSError against a 5000 h cap: the guard read 1000 and reported 4000 h of headroom where 1000 remained. The fix reconciles the ledger against the hours the state file records and takes the larger, warning when they differ. The asymmetry matters and is the reason it is not a plain equality check: the ledger is machine-global and the state file is one pipeline, so a ledger above the state file is the ordinary multi-pipeline case and says nothing, while the reverse cannot happen while every billed run reaches the ledger.
