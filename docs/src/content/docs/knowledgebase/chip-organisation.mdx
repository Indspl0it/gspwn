The streaming multiprocessor is the unit a GPU die repeats. Levels above the SM
distribute work to it and levels below it issue instructions within it. A
part's SM count and its compute capability together fix most of its compute
behaviour, and `cudaGetDeviceProperties` reports both.

## The containment chain

Five levels run from the die down to the unit a warp issues from.

| Level | Contains | Role |
| --- | --- | --- |
| Die | GPCs, memory partitions, the GigaThread engine, fixed-function engines | The physical chip |
| GPC | TPCs, a raster engine on graphics parts | The unit of work distribution |
| TPC | Two SMs, and geometry hardware on parts that have a graphics pipeline | A grouping inherited from the graphics pipeline |
| SM | Four processing blocks, a shared L1 and shared-memory array, load and store units | The unit a thread block is placed on |
| Processing block | A warp scheduler, a dispatch unit, a register file slice, execution lanes, one tensor core | The unit a warp is issued from |

A thread block never spans two SMs. A warp never spans two processing blocks.
Both facts follow from where the storage lives: a block's shared memory is
physically in one SM's array, and a warp's registers are physically in one
processing block's register file.

## Inside one SM

An H100 SM and an A100 SM differ in cache and shared-memory capacity and agree
on every scheduling cap.

| Resource | Per SM on an H100 | Per SM on an A100 |
| --- | --- | --- |
| Warp schedulers | 4, one per processing block | 4 |
| Register file | 256 KB, split as 64 KB per processing block | 256 KB, same split |
| L1 data cache and shared memory | 256 KB, configurable split | 192 KB |
| Maximum shared memory per block | 227 KB | 163 KB |
| Resident warps | 64, so 2048 threads | 64 |
| Resident thread blocks | 32 | 32 |
| Tensor cores | 4, one per processing block | 4 |

The caps interact, and occupancy is the minimum across all of them. The
register file binds most often, and no source line states its effect. 65,536
registers per SM, the 256 KB register file in 4-byte registers, divided by
threads-per-block times registers-per-thread gives a resident block count the
launch configuration never names. `ptxas -v` reports the register count the
compiler chose, and `cudaOccupancyMaxActiveBlocksPerMultiprocessor` computes
the resulting figure.

## Warps

The hardware scheduling unit is 32 threads. A block of 250 threads occupies 8
warps, and the last warp runs with 6 lanes masked off for its whole lifetime.
Block sizes that are not multiples of 32 waste lanes for that reason.

Four properties govern how a warp executes.

- Issue. One instruction per warp per cycle, from one warp scheduler.
- Divergence. Threads taking different branches are executed in separate passes
  with lanes masked.
- Reconvergence. Independent thread scheduling, from Volta onward, gives each
  thread its own program counter, so divergent threads can make forward
  progress independently.
- Latency hiding. A stalled warp is set aside and another resident warp issues
  in its place. An SM with more resident warps has more candidates to issue
  from, which is the effect occupancy measures.

Independent thread scheduling broke implicit warp synchronisation. Code written
before Volta that relied on lockstep execution within a warp requires
`__syncwarp` to remain correct, and the `_sync` suffixed intrinsics carry the
same requirement for the shuffle, vote and match operations.

## Variation by architecture

Six architectures span compute capability 7.0 to 12.x.

| Architecture | Compute capability | Notable change at the SM |
| --- | --- | --- |
| Volta | 7.0 | Independent thread scheduling. First tensor cores. Unified L1 and shared memory. |
| Turing | 7.5 | Tensor cores gain integer types. RT cores added on graphics parts. |
| Ampere | 8.0, 8.6 | Asynchronous copy from global memory to shared memory, bypassing registers. Third generation tensor cores. |
| Ada Lovelace | 8.9 | Fourth generation tensor cores with FP8. Larger L2. |
| Hopper | 9.0 | Thread block clusters, distributed shared memory across an SM group, the tensor memory accelerator. |
| Blackwell | 10.x, 12.x | Fifth generation tensor cores, further reduced precision formats. |

Compute capability names the SM's instruction set and resource limits. Two
parts sharing a compute capability accept the same compiled code and expose the
same per-SM limits, whatever their SM count.

## Partial dies

A shipping part rarely uses the whole die. Manufacturing defects are handled by
disabling the affected units and selling the result as a lower SKU, so the SM
count on a product page is smaller than the count in the architecture
whitepaper, and two SKUs cut from one die differ in SM count, memory bus width
and clock. A full GH100 die carries 8 GPCs of 9 TPCs of 2 SMs, 144 in total,
and the H100 SXM part ships 132 of them enabled.

| Quantity | Query |
| --- | --- |
| SM count | `cudaDeviceProp.multiProcessorCount` |
| Compute capability | `cudaDeviceProp.major` and `.minor` |
| Both, from the command line | `nvidia-smi --query-gpu=name,compute_cap --format=csv` |
