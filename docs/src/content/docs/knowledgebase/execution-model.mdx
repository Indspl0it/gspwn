A CUDA launch describes work as a grid of thread blocks. The hardware sees
streaming multiprocessors, warp schedulers and lanes. A streaming
multiprocessor, or SM, is one of the repeated compute units a GPU is built
from, with its own register file, its own shared memory and its own
schedulers. Four correspondences connect the two views. The block-to-SM
correspondence determines occupancy, because a block's registers and shared
memory are drawn from one SM's budget.

## The mapping

Four software levels correspond to four hardware levels, one for one.

| Software | Hardware | Consequence |
| --- | --- | --- |
| Grid | One device | A launch targets one GPU. Multi-GPU work is several launches. |
| Thread block | One SM | A block's registers and shared memory come from one SM's budget, so a block asking for more than an SM has never launches |
| Warp | One warp scheduler issue slot | 32 threads share an instruction stream. Divergence within a warp costs execution time. |
| Thread | One lane | Each thread has its own registers and, since Volta, its own program counter |

A warp is the fixed group of 32 threads the hardware issues an instruction to
as a unit. A lane is one thread's slot in that group. Neither appears in the
source: the compiler and the hardware split every block into warps of 32.

Blocks are scheduled onto SMs in no defined order and cannot communicate with
each other during a launch. One binary therefore runs on a part with 20 SMs and
on a part with 132: the runtime hands blocks to whatever SMs exist.

Hopper adds a level between grid and block. A thread block cluster groups
blocks that are guaranteed to be resident on SMs within one GPC, which lets
them address each other's shared memory. It is the first mechanism that lets
blocks cooperate.

## Warps and divergence

The scheduler issues one instruction for a warp, and every lane executes it.

When threads in one warp take different branches, the warp executes both paths
and masks off the lanes that are inactive for each. The cost is the sum of the
path lengths.

<WarpDivergence />

Under the first predicate every warp runs `A` with 16 lanes masked off, then
`B` with the other 16 masked off, which idles 32 lane-slots across the two
passes. The second predicate is constant across a warp, so each warp runs one
path, skips the other entirely, and idles nothing.

Volta changed what happens after divergence. Before it, a warp had a single
program counter and threads were forced back into lockstep at the reconvergence
point. Volta gave each thread its own program counter, so diverged threads can
make independent progress. That makes some previously deadlocking patterns work
and makes code that assumed implicit warp-synchronous behaviour unsafe.
`__syncwarp()` is the explicit form that replaced the assumption.

## Occupancy

Occupancy is resident warps per SM against the architectural maximum. It is a
latency-hiding measure: while one warp waits on memory, the scheduler issues
from another.

| Limit | Set by | Effect when it binds |
| --- | --- | --- |
| Registers per thread | The compiler, capped by `-maxrregcount` or `__launch_bounds__` | Fewer blocks fit per SM |
| Shared memory per block | The kernel's declared shared memory | Fewer blocks fit per SM |
| Threads per block | The launch configuration, at most 1024 | A block granularity that leaves warp slots unused |
| Blocks per SM | The architecture | An upper bound reached with small blocks |

The binding limit is whichever runs out first. A kernel using 64 registers per
thread on a part allowing 65536 registers per SM fits 1024 threads, which is
32 warps, whatever the other limits allow.

A kernel with enough independent work in flight per thread reaches peak
throughput below full occupancy, and spending registers to reach that state can
raise throughput.

## Launch configuration

Four slots go inside the triple angle brackets of a launch. The first two set
the shape of the work and the last two set the resources and the ordering it
runs under.

Block dimensions that are not a multiple of 32 waste lanes, because the
hardware still issues a whole warp for the remainder. A block of 100 threads
occupies four warps and runs the fourth with 28 of its 32 lanes masked off.
