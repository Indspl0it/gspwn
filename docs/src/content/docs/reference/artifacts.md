title: Artifacts
description: The artifacts tree, the run directory layout, and the CSV columns.

The repository separates what a campaign produces from what a campaign reads.
`artifacts/` holds the first and is gitignored in full, down to a `.gitkeep`
per directory that version-controls the tree shape. The second lives in three
top-level trees that are committed without exception:
[`surface/`](#surface-artefacts), `descriptions/` and `harnesses/`.

The split is mechanical. A clean checkout carries every input CI needs and no
campaign state at all, and `.gitignore` names `artifacts/` once with no
per-file exceptions.

## Campaign output

Gitignored. Nothing here survives a fresh clone.

| Path | Contents | Written by | Lifetime |
|---|---|---|---|
| `artifacts/builds/` | `manifest.json`, per-rung failure notes, conftest patches | `build_kernel.sh`, `build`, `provision` | Per machine |
| `artifacts/bulletins/` | PSIRT bulletin pages, one per advisory number | `cve_patch_map.py fetch` | Cache |
| `artifacts/corpus/` | Reserved. No tool in `tools/` writes here | (none) | (none) |
| `artifacts/crashes/` | `QUEUE.md`, `pstore-<stamp>/` harvest directories | `triage`, `crashlog_ctl.py harvest` | Per campaign |
| `artifacts/eval/` | `description-audit.md`, `rca-audit.md`, `version-persistence.md`, `<run-id>/` | `eval`, `refine` | Per round |
| `artifacts/logs/` | `<name>.log`, build logs | `exec.py` | Per machine |
| `artifacts/pocs/` | `<crash-id>/` | `poc`, `repro_ctl.py extract` | Per crash |
| `artifacts/rca/` | `<crash-id>.md` | `rca` | Per crash |
| `artifacts/report/` | `<date>-report.md`, `disclosure/<crash-id>/` | `report` | Once per pipeline |
| `artifacts/runs/` | `<run-id>/` | `campaign_ctl.py`, `coverage_ctl.py`, syz-manager | Per campaign |
| `artifacts/seeds/` | `*.syz`, `promoted.json`, `trace.txt` | `seeds`, `trace2seed.py`, `corpus_ctl.py promote` | Outlives rounds and campaigns |
| `artifacts/src/` | `linux`, `open-gpu-kernel-modules`, `syzkaller`, `nvidia-container-toolkit`, `libnvidia-container` | `provision` | Per machine |
| `artifacts/u-crashes/` | `<harness-name>/`, each crash input beside its `.sanlog` replay report | `run_all.sh`, `replay_crashes.sh` | Per campaign |

The completion ledger is campaign progress and sits in `state/`, beside
`pipeline.json`. [Completion ledger](#completion-ledger) covers its schema.

## Committed input

| Path | Contents | Written by | Lifetime |
|---|---|---|---|
| `descriptions/` | The syzlang description set, `nvidia_gspwn.h`, `generation.json` | `syzlang_gen.py emit`, `describe` | Per driver release |
| `harnesses/` | `TARGETS.md`, `build_all.sh`, `run_all.sh`, `replay_crashes.sh`, `<harness>/` | Hand-written | Per toolkit release |
| `surface/` | The three inventories, the derived artefacts, the round-1 worklist | The surface extractors, `refine` | Per driver release |

`harnesses/<harness>/build/` holds compiler output and is the one gitignored
path inside a committed tree.

## Run directory

The run id is of the form `r<round>-<n>` and covers both tracks. The coverage
sampler and the deadline timer key on the single id.

| Path under `artifacts/runs/<run-id>/` | Contents |
|---|---|
| `deadline` | An absolute epoch second, fsynced at install time |
| `syz-manager.cfg` | Generated by `campaign_ctl.py gen-config` |
| `coverage.csv` | Track K samples |
| `coverage-u.csv` | Track U samples |
| `workdir/` | syz-manager's own directory |
| `workdir/corpus.db` | The only corpus input syz-manager reads |
| `workdir/crashes/<hash>/` | `description`, `report<N>`, `log<N>`, `repro.prog`, `repro.cprog` |
| `u/<harness>/` | Track U fuzzer output: `fuzzer_stats`, `queue/`, `corpus/` |

## Coverage CSV columns

Both `coverage.csv` and `coverage-u.csv` carry the same header.

| Column | Type | Contents |
|---|---|---|
| `ts` | integer | Unix timestamp of the sample |
| `uptime_s` | integer | Fuzzer uptime, where the source reports one |
| `edges` | integer | Distinct edges reported |
| `corpus` | integer | Program count |
| `corpus_bytes` | integer | The corpus database's byte size, from the fallback source only |
| `crashes` | integer | Crashes the fuzzer counted |
| `execs` | integer | Executions performed |
| `source` | string | Which source answered |
| `gpu` | string | GPU status, or `n/a` on Track U |
| `disk_free_mb` | integer | Free megabytes on the artifacts filesystem |
| `surface` | integer | Enumerated targets this run's corpus names, empty when the sample did not measure it |

`corpus` is a program count and `corpus_bytes` is a file size. They are kept as
separate columns so that a comparison spanning a source change stays valid.

Rows are appended under the header the file already carries. A run that started
before a column existed keeps its shape, and rows missing the `gpu` column read
as unrecorded, which makes a plateau verdict over them `unknown`.

Source and GPU values: [Closed vocabularies](/gspwn/reference/vocabularies/).

## PoC directory

| Path under `artifacts/pocs/<crash-id>/` | Track | Contents |
|---|---|---|
| `README.md` | Both | Build steps, run steps, expected signature, rate, profile-check outcome, preconditions |
| `repro.prog` | K | The syzkaller program, stored under this name whichever of `repro.prog` and `repro.syz` the crash directory carried |
| `repro.cprog` | K | syz-manager's own C translation of that program |
| `repro.c` | K | Copied from `repro.cprog`, or generated by `syz-prog2c` from `repro.prog` |
| `repro` | K | The compiled reproducer |
| `report` | K | The registered crash report, normalised from the lowest-numbered `report<N>` |
| `repro.report`, `repro.stats` | K | syz-repro's own report and statistics for the reproducer run |
| `description` | K | The registered title |
| `log` | K | The syzkaller execution log, normalised from the lowest-numbered `log<N>` |
| `input` | U | The crash input |
| `last-run.log` | U | The last replay's output and exit code |

## Harvest directory

| Path under `artifacts/crashes/pstore-<YYYYmmdd-HHMMSS>/` | Environment | Contents |
|---|---|---|
| `dmesg-ramoops-0` | Bare metal | Copied out of `/sys/fs/pstore` |
| `console-output.log` | EC2 | `aws ec2 get-console-output --latest` |
| `kdump-<name>/` | Both | One per unharvested `/var/crash` directory, holding `dmesg.<stamp>` and `dump.<stamp>` |

The directory is named for the time the harvest ran. `repro_ctl.py` treats a
harvest older than the current boot as absent, because it cannot describe the
run that just killed the machine.

`vmcore` files are skipped by every reader: they are too large to scan, and the
dmesg or console text alongside them carries the signature.

## Seed bank

| Path under `artifacts/seeds/` | Written by | Contents |
|---|---|---|
| `seed-NNNN.syz` | `trace2seed.py` | Seed programs derived from traces |
| `promoted-<run-id>-<hash>.syz` | `corpus_ctl.py promote` | Programs promoted out of a finished run's corpus |
| `promoted.json` | `corpus_ctl.py promote` | The promotion ledger: content hash to file name and source run |
| `trace.txt` | `seeds` | The strace the seeds came from |

`promoted.json` is written atomically through a temporary file and a rename.

## Round outputs

| Path under `artifacts/eval/<run-id>/` | Contents |
|---|---|
| `gaps.md` | One row per gap: the ioctl or subsystem, the evidence, the classification, the specific next action |
| `worklist.md` | Ordered items for the next round, split into `describe` and `seeds` sections, every item tagged `[surface]`, `[finding crash-NNNN]` or `[history CVE-YYYY-NNNNN]` |

`artifacts/eval/version-persistence.md` holds either the per-PoC persist or
fixed table, or the single line `skipped: <why>`. Both are acceptable results.
The `eval` gate requires the file to exist.

## Surface artefacts

`surface/` reduces the driver source and the fix history to the form
the phases read, before any campaign runs. Every file here is keyed to one driver
release.

| Path under `surface/` | Written by | Read by |
|---|---|---|
| `ioctl-inventory.json` | `ioctl_inventory.py` | `syzlang_gen.py`, `surface_cov.py`, `regression_check.py`, `refgen.py` |
| `ioctl-sizes.json` | The runner `ioctl_inventory.py --emit-probe` writes, which needs the driver headers compiled | `ioctl_inventory.py` as the `--sizes` default. 184 measured struct sizes, of which 183 resolve a dispatched escape or UVM command |
| `rm-control-inventory.json` | `ctrl_surface.py` | `syzlang_gen.py`, `surface_cov.py`, `object_graph.py chains`, `ctrl_rank.py`, `regression_check.py`, `refgen.py` |
| `rm-object-graph.json` | `object_graph.py extract` | `syzlang_gen.py`, `surface_cov.py`, `cve_patch_map.py`, `refgen.py` |
| `ctrl-param-sizes.json` | `syzlang_gen.py emit-probe` and its runner | `syzlang_gen.py emit` as the `--ctrl-sizes` default, `ctrl_rank.py` |
| `rm-chains.json` | `object_graph.py chains` | `trace2seed.py chains`, `ctrl_rank.py`, `refgen.py` |
| `rm-control-rank.json` | `ctrl_rank.py rank` | `syzlang_gen.py emit` as the `--ctrl-rank` default, `trace2seed.py chains`, `refgen.py` |
| `cve-hotspots.json`, `prior-cves.json` | `cve_patch_map.py` | `ctrl_rank.py` reads the hot spots. `refgen.py` joins both |
| `completion-ledger.json` | `pipeline_ctl.py surface-account` | `coverage_ctl.py completion`, `pipeline_ctl.py surface-ledger` |
| `worklist-round1.md` | `cve_patch_map.py worklist` | The round-1 `describe` and `seeds` phases |
| `bulletins/` | `cve_patch_map.py fetch` | `cve_patch_map.py resolve` |

## Completion ledger

`surface/completion-ledger.json`, schema `gspwn.surface-ledger/1`.
One row per target that carries a written reason for not being exercised. The
round records its path under `rounds[-1].surface_ledger`, stored repo-relative.

| Field | Contents |
|---|---|
| `schema` | `gspwn.surface-ledger/1` |
| `driver_version` | The release the accounted rows were written against |
| `targets_total` | The denominator at that release |
| `updated` | Timestamp of the last write |
| `accounted` | Target key to row |

| Row field | Contents |
|---|---|
| `key` | The composite ABI identity, and the mapping key |
| `variant` | The syzlang call name a corpus program carries |
| `family` | `escape`, `uvm`, `uvm_tools`, `control` or `alloc` |
| `reason` | One of the closed vocabulary in [Closed vocabularies](/gspwn/reference/vocabularies/) |
| `detail` | The written reason, refused when empty |
| `evidence` | `file.c:line` entries, required for five of the eight reasons |
| `round` | The round that recorded it |
| `first_recorded`, `recorded` | First write and last write |

The ledger is its own artefact and not part of `state/pipeline.json`, which is
1177 bytes and is rewritten whole under a lock on every phase transition and
every crash registration. `GSPWN_SURFACE_LEDGER` overrides the path.

## Committed paths

| Path | Committed | Reason |
|---|---|---|
| `artifacts/**` | No | Campaign output. `.gitkeep` alone is committed, to version-control the tree shape |
| `state/**` | No | Machine state. `.gitkeep` alone is committed |
| `surface/*.json` | Yes | The three inventories are the 764-target denominator, the derived artefacts key on them, and CI computes neither without a driver source tree it does not have |
| `surface/worklist-round1.md` | Yes | Round 1 reads it before any campaign has run |
| `descriptions/*.txt`, `nvidia_gspwn.h`, `generation.json` | Yes | The numerator CI compares against the denominator, and the digests the set was emitted at |
| `harnesses/**` | Yes | Hand-written C and Go that no phase regenerates |
| `harnesses/*/build/` | No | Compiler output from `build_all.sh` |
| `knowledge/*.md` | Yes | Carried across a rebuilt box |
| `knowledge/*.lock` | No | Lock state |
| `tools/ioctl_map.json`, `tools/cve_fix_verdicts.json` | Yes | Static data |
| `config/*.yaml` | Yes | Shipped configuration |

Sizes are uneven. `surface/cve-hotspots.json` is 4.4 MB, the largest committed
file in the tree, and `refgen.py` joins it with `prior-cves.json` to build
`reference/surface/driver-cves.md`, which `regression_check.py pages`
regenerates in CI.

Every path a committed artefact records is relative to the repository root.
`repo_relative()` in the four surface extractors enforces it, and
`selftest.py` fails on an absolute path in any file under `surface/` or
`descriptions/`. An extractor that wrote `os.path.abspath()` put a home
directory into a shipped file and made the same driver source produce
different bytes under Windows and under WSL.
