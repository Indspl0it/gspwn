## Request number encoding

The RM node encodes a Linux `_IOWR` request number over the bare escape number and the measured size of the parameter struct. The three UVM nodes pass the bare command number and encode nothing.

| Field | Value | Source |
|---|---|---|
| `ioctl` magic | 70 | `NV_IOCTL_MAGIC` |
| Escape number base | 200 | `NV_IOCTL_BASE` |
| Direction bits | 3 | `kernel-open/common/inc/nv.h:84 (__NV_IOWR)` |
| Size field width, bits | 14 | `_IOC_SIZEBITS` |
| Largest encodable size, bytes | 16383 | `_IOC_SIZEMASK` |
| UVM stack parameter ceiling, bytes | 288 | `UVM_MAX_IOCTL_PARAM_STACK_SIZE` |
| Oversize transfer escape | `NV_ESC_IOCTL_XFER_CMD` | `nv_ioctl_xfer_t` |

The artefact records one limit note against this encoding:

> NV_PLATFORM_MAX_IOCTL_SIZE, the per-platform ceiling __NV_IOWR_ASSERT enforces, is not defined in the open modules. IOC_SIZE_MAX is the architectural limit; the real switchover to XFER may happen lower.

## Declared escapes with no dispatch site

These names are defined in `nv_escape.h` and mentioned by no switch and no table. Declared and unreachable is a separate state from undocumented, and it decides whether a description for the escape is worth authoring. The artefact records the name alone, because with no dispatch site there is no case body to read a parameter struct or a device-node restriction from.
